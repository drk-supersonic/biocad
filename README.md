# Gantt AI Planner

Full-stack тестовое задание: интерактивная диаграмма Гантта с редактированием
плана через чат на естественном языке (LLM + MCP).

## Структура репозитория

```
backend/       FastAPI + MCP-сервер, см. backend/README.md
frontend/      React + диаграмма Гантта + чат, см. frontend/README.md
render.yaml    Blueprint для деплоя на Render (backend: Web Service, frontend: Static Site)
ROADMAP.md     Что нужно доработать для боевого состояния: техдолг, риски, план
```

## Архитектура (кратко)

- **Бэкенд**: FastAPI-хост + MCP-сервер (`FastMCP`) в одном процессе,
  соединены через in-memory MCP-transport (без отдельного OS-процесса и
  stdio). REST-эндпоинты (`/api/tasks`, `/api/upload-excel`,
  `/api/export-excel`) — прямые вызовы; `/api/chat` — та же MCP-сессия,
  но вызовы инструментов инициирует LLM (OpenRouter, tool-calling).
  Подробности — `backend/README.md`.
- **Фронтенд**: React + `gantt-task-react` для диаграммы, чат-панель и
  модалка задачи. Вся правда о плане — на бэкенде, фронт только
  отображает и шлёт команды. Подробности — `frontend/README.md`.

## Деплой

Через Render Blueprint (`render.yaml` в корне):
1. dashboard.render.com → New → Blueprint → подключить этот репозиторий.
2. Render создаст два сервиса: `gantt-backend` (Web Service) и `gantt-frontend`
   (Static Site) — переменные окружения уже прописаны в `render.yaml`.
3. Ключ OpenRouter **не** прописывается на бэкенде — пользователь вводит его
   в поле в интерфейсе, он уходит в теле запроса `/api/chat` и нигде на
   сервере не сохраняется (см. `backend/README.md`).
4. Если имена `gantt-backend`/`gantt-frontend` уже заняты на Render — он
   добавит случайный суффикс к URL; тогда поправь `CORS_ORIGINS` в backend и
   `VITE_API_URL` в frontend на реальные адреса и сделай redeploy.

Известное ограничение текущего деплоя (бесплатный план Render, "холодный
старт" после простоя) описано в `ROADMAP.md`.

## Локальный запуск

См. `backend/README.md` и `frontend/README.md` — запускать нужно оба
(бэкенд первым).

## Использование AI-ассистентов при разработке

Разрабатывал с Claude (Anthropic) на всех этапах — от архитектуры до деплоя.

**Backend + MCP.** Вместе с Claude спроектировали архитектуру: FastAPI-хост,
MCP-сервер на FastMCP с инструментами для правки плана (add_task, move_task,
set_dependencies и т.д.), планировщик расписания с пересчётом дат по
зависимостям. Код писал Claude, я проверял логику руками — гонял сценарии
(перенос задачи, добавление, удаление) через тестовый скрипт и смотрел, что
даты пересчитываются правильно и каскадно сдвигают зависимые задачи.

**Деплой.** Разворачивал на Render с помощью Claude пошагово — от создания
Blueprint до разбора ошибок в логах, когда что-то не поднималось с первого
раза (например, несовпадение версий зависимостей, а позже — конфликт
встроенного шага установки зависимостей Render с patch-package).

**Frontend.** Первую версию (диаграмма Гантта, чат, модалка задачи) собрал
Claude, я тестировал в браузере и присылал скриншоты багов (нечитаемый текст
на диаграмме, наезжающие даты в шапке) — Claude находил причину и правил.

**Вторая итерация.** Дальше дорабатывал в отдельной сессии с Claude:
переход MCP-сервера на in-memory transport вместо отдельного процесса
(быстрее отвечает на каждый запрос), отказ от pandas в парсинге Excel в
пользу прямого openpyxl (меньше зависимостей — быстрее холодный старт на
бесплатном плане Render), переработка UI и переключатель масштаба
диаграммы (день/неделя/месяц), локализация шапки диаграммы под patch-package.

**Что делал сам:** финальную проверку сценариев в браузере на задеплоенной
версии, чтение и правку промптов там, где модель в чате плохо понимала
задачи (например, переходил на более подходящую по цене/качеству модель,
когда стало ясно, что дешёвая версия слишком часто переспрашивает),
структуру и содержание этого README и ROADMAP.md.

Практически весь код брал как сгенерировал Claude — руками правил точечно,
когда видел баг или не устраивал результат после проверки.
