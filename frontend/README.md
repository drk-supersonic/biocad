# Frontend (React + диаграмма Гантта + чат)

## Стек

- React 18 + Vite
- `gantt-task-react` — визуализация диаграммы Гантта
- Никаких состояний на клиенте кроме React state — вся правда о плане
  хранится на бэкенде (через MCP), фронт просто её отображает и шлёт команды

## Запуск локально

```bash
cd frontend
npm install
cp .env.example .env.local
# при необходимости поправь VITE_API_URL в .env.local (по умолчанию localhost:8000)
npm run dev
```

Открой http://localhost:5173 — бэкенд должен быть уже запущен (см. ../backend/README.md).

## Тесты

```bash
npm test
```

Smoke-тесты на jsdom для диаграммы, модалки и чат-панели (рендер без ошибок,
базовые сценарии типа "нет ключа — просим ввести").

## Ключ OpenRouter

Вводится в поле в шапке приложения, хранится только в React state (в памяти
вкладки), нигде не сохраняется — ни в localStorage, ни на сервере. При
обновлении страницы его нужно ввести заново. Отправляется на бэкенд только
в теле запроса `POST /api/chat`.

## Почему `isDisabled: true` на задачах в диаграмме

Редактирование плана в этом MVP идёт только через чат (агент вызывает MCP-
инструменты), а не через drag-n-drop прямо на диаграмме — так весь путь
изменений идёт через LLM+MCP, как того требует ТЗ, и не расходится с тем,
что видит и что подтверждает пользователь в чате. Drag-n-drop на самой
диаграмме — кандидат в Roadmap to production.
